# Axon 项目需求分析

## 一、项目概述

### 1.1 项目名称
**Axon** - 跨平台个人代码知识库与多视图 Markdown 工具

### 1.2 项目定位
Axon 是一款基于 Tauri v2 + React 19 构建的**跨平台个人代码知识库桌面应用**。它提供「一份 Markdown，多种视图」的文档处理体验，并通过 MCP（Model Context Protocol）协议将个人知识库暴露给外部 AI 工具，实现「越用越懂你」的智能编码体验。

**核心价值主张**：
- **编辑器**：类 Typora 的所见即所得 Markdown 编辑
- **多视图**：编辑器 / 脑图 / 演示三种视图无缝切换
- **知识库**：Markdown 文件 + Frontmatter 标签体系，结构化管理代码经验
- **MCP 集成**：通过标准协议让 Cursor / Claude 等 AI 工具实时检索你的知识库

### 1.3 目标用户
- 希望系统化积累编程经验的开发者
- 技术文档编写者与知识管理爱好者
- 需要进行技术演示的工程师
- 追求「AI 越来越像自己写代码」的效率极客

### 1.4 核心设计理念

**Single Source of Truth（单一数据源）**

Markdown 是 Axon 中唯一的数据源。编辑器、思维导图、演示文稿都是同一份 Markdown 的不同「投影」。用户在任何视图中的修改，最终都会同步回 Markdown 文本。

```
用户编辑 Markdown
       │
       ├──→ Tiptap 编辑器 (编辑视图)
       │
       ├──→ markmap 解析 → 脑图渲染 (脑图视图)
       │
       ├──→ remark 解析 → reveal.js 渲染 (演示视图)
       │
       └──→ MCP Server → 外部 AI 工具消费 (知识库接口)
```

**设计原则：**
1. **数据驱动视图**：三种视图共享同一份 Markdown 状态（Zustand），切换视图时实时转换渲染
2. **编辑器常驻**：文档视图和脑图视图中，右侧的 Markdown 编辑器始终可见，保证随时可编辑
3. **视图即投影**：脑图是 Markdown 层级结构的可视化，演示是按分隔符切分后的幻灯片序列
4. **无感知积累**：用户正常写文档的过程就是在积累知识库，无需额外操作

## 三、功能需求

### 3.1 核心功能模块

#### 3.1.1 Markdown 编辑器 (Editor)
**状态**: 待实现

**功能描述**:
- 基于 Tiptap 构建的所见即所得 Markdown 编辑器
- 支持常见 Markdown 语法（标题、列表、代码块、链接、图片等）
- 代码块语法高亮（lowlight）
- 实时预览与源码模式切换

**技术实现**:
- `@tiptap/react` - 编辑器核心
- `@tiptap/starter-kit` - 基础扩展
- `@tiptap/extension-code-block-lowlight` - 代码块高亮

#### 3.1.2 思维导图视图 (Mindmap)
**状态**: 待实现

**功能描述**:
- 将 Markdown 文档结构自动转换为思维导图
- 支持缩放、拖拽、节点展开/折叠
- 导出为图片

**双路线策略**:

| 路线 | 库 | 职责 | 交互方式 |
|------|-----|------|---------|
| A: 只读预览 | `markmap-lib` + `markmap-view` | Markdown → 脑图自动渲染 | 缩放、展开/折叠，不可编辑节点 |
| B: 可编辑脑图 | `@xyflow/react` | 节点拖拽、新增、删除 | 编辑节点后同步回 Markdown |

- 初期优先实现路线 A（markmap 只读预览），快速出效果
- 后续迭代路线 B（ReactFlow 可编辑），实现脑图 ↔ Markdown 双向同步

#### 3.1.3 演示文稿视图 (Presentation)
**状态**: 待实现

**功能描述**:
- 将 Markdown 转换为幻灯片演示
- 支持多种主题和过渡效果
- 演讲者模式
- 导出 PDF

**Markdown 分割规则**:
- 一级标题 `# ` 作为幻灯片章节分隔（水平切换）
- `---`（三条横线）作为同一章节内的页面分隔（垂直切换）
- 若文档中无 `---`，则每个一级/二级标题自动成为一张幻灯片

**技术实现**:
- `reveal.js` - 幻灯片框架
- `unified` + `remark-parse` + `remark-rehype` - Markdown 转 HTML

#### 3.1.4 知识库管理 (Knowledge Base)
**状态**: 待实现

**功能描述**:
- 指定一个本地目录作为知识库根目录（KB_ROOT）
- 知识库中的 Markdown 文件遵循 Frontmatter 规范，便于分类检索
- 支持按标签、关键词、目录浏览和搜索知识库内容
- 新建/编辑文档时自动引导填写 Frontmatter 元数据

**Markdown 文件规范**:

```markdown
updated: 2026-03-06
---

# FastAPI JWT 登录认证

## 概述
使用 PyJWT 实现 FastAPI 的 Token 认证...

## 代码实现
...
```

**知识库目录结构**:

#### 3.1.5 MCP 服务端 (MCP Server)
**状态**: 规划中

**功能描述**:
- 内置一个独立的 MCP Server（Node.js CLI），通过 stdio 与外部 AI 工具通信
- 暴露两个核心工具给 AI：
  - `search_kb`：按关键词/标签搜索知识库，返回匹配文件列表
  - `read_kb_file`：读取指定知识库文件的完整内容
- 随 Axon 安装后，用户可在 Cursor / Claude Desktop 中配置使用

**架构设计**:
```
┌──────────────────┐     stdio      ┌──────────────────┐
│  Cursor / Claude │ ◄────────────► │  Axon MCP Server │
│  (AI 客户端)      │                │  (Node.js CLI)   │
└──────────────────┘                └────────┬─────────┘
                                             │ 读取
                                    ┌────────▼─────────┐
                                    │   Knowledge Base  │
                                    │   (本地 .md 文件)  │
                                    └──────────────────┘
```

**使用流程**:
1. 用户在 Axon 中编写/保存 Markdown 知识文档
2. 用户在 Cursor 配置中注册 Axon MCP Server
3. 用户向 AI 提问：「实现一个 JWT 登录功能，参考我的知识库」
4. AI 自动调用 `search_kb` → 找到匹配文档 → 调用 `read_kb_file` 读取内容
5. AI 结合知识库内容生成符合用户习惯的代码

**进阶规划**:
- 初期：基于 Flexsearch 的全文关键词搜索
- 中期：基于向量数据库的语义搜索（搜「验证身份」能找到「登录认证」）
- 长期：文件监听（chokidar），新增/修改文件时自动更新索引

## 四、非功能性需求

### 4.1 性能

| 指标 | 要求 |
|------|------|
| 大文档编辑 | 10 万字以内的 Markdown 文件编辑流畅，无明显卡顿 |
| 视图切换 | 编辑器 ↔ 脑图 ↔ 演示切换延迟 < 500ms |
| 启动速度 | 应用冷启动 < 3 秒 |
| 知识库搜索 | 1000 个文件以内，搜索响应 < 200ms |

### 4.2 安全

| 要求 | 说明 |
|------|------|
| 文件系统隔离 | MCP Server 严格限制在 KB_ROOT 目录内，防止路径遍历攻击 |
| 本地优先 | 所有数据存储在本地，MCP 仅通过 stdio 通信，不开放网络端口 |
| 权限最小化 | Tauri capabilities 仅授予必要的文件系统和对话框权限 |

### 4.3 可用性

| 要求 | 说明 |
|------|------|
| 键盘快捷键 | 支持常用快捷键（Ctrl+S 保存、Ctrl+O 打开等） |
| 深色/浅色模式 | 跟随系统或手动切换 |
| 自动保存 | 可配置的自动保存间隔 |

## 五、数据模型

### 5.1 文档状态 (DocumentState)

```typescript
interface DocumentState {
  content: string;         // Markdown 内容
  filePath: string | null; // 当前文件路径
  viewMode: ViewMode;      // 当前视图模式
  isDirty: boolean;        // 是否有未保存修改
}

type ViewMode = "editor" | "mindmap" | "presentation";
```

### 5.2 文档元数据 (DocumentMeta)

```typescript
interface DocumentMeta {
  title: string;
  createdAt: string;
  updatedAt: string;
}
```

### 5.3 知识库文档 (KBDocument)

```typescript
interface KBDocument {
  filePath: string;        // 相对于 KB_ROOT 的路径
  title: string;           // Frontmatter 中的 title
  tags: string[];          // Frontmatter 中的 tags
  category: string;        // Frontmatter 中的 category
  created: string;
  updated: string;
  content: string;         // Markdown 正文内容
}
```

### 5.4 知识库索引 (KBIndex)

```typescript
interface KBIndex {
  version: number;
  lastUpdated: string;
  documents: KBIndexEntry[];
}

interface KBIndexEntry {
  filePath: string;
  title: string;
  tags: string[];
  category: string;
  updated: string;
  contentHash: string;     // 用于检测文件变更
}
```
